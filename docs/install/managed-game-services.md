# Managed game-server services on Linux

The default `direct` lifecycle keeps existing behavior: the panel launches the
Project Zomboid process itself. Linux administrators can opt a local server
profile into `systemd` or OpenRC instead. In that mode, the operating-system
service owns the game process. Restarting or updating the panel does not stop
the game server.

Container and remote profiles cannot use this feature. Container installations
keep their image- and container-based lifecycle.

## Safe migration

1. Stop the game server and confirm that no Project Zomboid server process is
   still running.
2. Open **My Servers**, edit the profile, and select `systemd` or OpenRC under
   **Lifecycle Provider**.
3. Download the generated service file. Review its user, paths, launcher, and
   ownership marker.
4. Install it as the same account that runs the panel, at the path shown by the
   panel. The panel never runs `sudo` and never writes to `/etc`.
5. Complete the one-time user-service session setup described below. The panel
   controls only that account's user service manager and needs no root service
   management permission.
6. Return to the dialog and activate the provider.

Activation fails closed when the installed service is missing, is already
running, has an ownership marker for another server profile, or the panel
cannot prove that the previous process is stopped. This prevents an existing
process from being adopted silently.

The generated names use the immutable panel profile ID:

```text
zomboid-panel-server-<profile-id>.service  # systemd
zomboid-panel-server-<profile-id>          # OpenRC
```

Static reference templates are available in `service-templates/`. Prefer the
file generated by the panel because it contains the profile's validated paths
and ownership marker.

## systemd

Install the downloaded user unit as the panel service account, reload its user
manager, and enable it:

```sh
install -d -m 0755 ~/.config/systemd/user
install -m 0644 ./zomboid-panel-server-<id>.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable zomboid-panel-server-<id>.service
```

An administrator must enable lingering once so the account's user manager is
available without an interactive login and remains available across panel
restarts:

```sh
sudo loginctl enable-linger <panel-user>
```

Do not start it before activating the provider. The activation preflight
requires the service to be installed but stopped.

## OpenRC

Recent OpenRC releases support user services. Install the script in the panel
account's user-service directory and add it to that user's default runlevel:

```sh
install -d -m 0755 ~/.config/rc/init.d
install -m 0755 ./zomboid-panel-server-<id> ~/.config/rc/init.d/
rc-update --user add zomboid-panel-server-<id> default
```

OpenRC user services require `XDG_RUNTIME_DIR` and a running user-service
session. Configure the distribution's `pam_openrc`/`openrc-user` integration,
or its documented boot-time `user.<name>` service, before activation. The
panel derives `XDG_RUNTIME_DIR` from its own numeric user ID when the service
environment does not provide it.

Again, leave it stopped until the provider activation succeeds.

## Rollback to direct mode

Stop the managed service first. Select `direct` and confirm the migration. The
panel refuses the switch if the service is still running or its state cannot be
verified. After the provider changes, disable and remove the old unit manually
if it is no longer needed.
